# نسخه عملیاتی Read-Only دستیار پشتیبانی پرگار

## نمای کلی کل برنامه

برای دیدن شکل کلی برنامه و ارتباط ماژول‌ها، صفحه [`app-shell.html`](app-shell.html) را باز کنید. این صفحه داشبورد، Case Review، Smart Troubleshooting و مسیر مستندات را یکجا نمایش می‌دهد.

فایل `index.html` یک نمونه نمایشی کاملاً محلی است. داده تستی در SQLite داخلی
`data/pargar-support.sqlite3` نگهداری می‌شود و هیچ تغییری به CRM برنمی‌گردد.

برای مشاهده:

1. برای چند Case واقعی، ابتدا `python scripts/sync_crm_to_local.py` را اجرا کنید. این فرمان ۱۰ Case اخیر و Note/Task مرتبط را واکشی می‌کند.
2. مسیر اصلی برنامه فقط از `python scripts/sync_crm_to_local.py` برای واکشی Snapshot واقعی CRM استفاده می‌کند و در صورت خطای اتصال با داده نمونه ادامه نمی‌دهد.
3. برای اجرای رابط متصل به دیتابیس داخلی، `python scripts/local_app.py` را اجرا کنید.
4. نشانی `http://127.0.0.1:8765/` را با Chrome یا Edge باز کنید.
5. از فهرست Caseها، Case موردنظر را انتخاب و بازبینی کنید.

در حالت Snapshot واقعی، فهرست Caseها از دیتابیس داخلی نمایش داده می‌شود. با انتخاب هر Case:

- عنوان، شرح، وضعیت و فیلدهای قابل‌دسترس همان Case نمایش داده می‌شود.
- Noteهای ارتباط کارشناس و مشتری، Postهای داخلی و Taskهای مرتبط همان Case نمایش داده می‌شوند.
- Task با نقش داخلی L2 در مدل داده برچسب‌گذاری می‌شود؛ ثبت آن در CRM انجام نمی‌شود.
- کمبودهای اطلاعاتی و سؤال‌های تکمیلی بر اساس متن همان Case محاسبه می‌شوند.
- مقاله‌های KB با امتیازدهی ساده هم‌پوشانی متن پیشنهاد می‌شوند.
- پیش‌نویس Note از همان Case ساخته می‌شود.

این نسخه عملیاتی خواندنی:

- با Snapshot داخلی کار می‌کند؛ Snapshot می‌تواند واقعی یا ساختگی باشد.
- رابط به CRM وصل نمی‌شود؛ فقط از SQLite داخلی می‌خواند.
- بازخوردها فقط در SQLite داخلی ذخیره می‌شوند.
- هیچ عملیات نوشتن به CRM انجام نمی‌شود.
- پذیرش، رد، ویرایش و تکمیل نمونه را فقط در رابط صفحه شبیه‌سازی می‌کند.

این نسخه برای استفاده عملیاتی خواندنی آماده است؛ ثبت نهایی در CRM، احراز هویت سازمانی و RBAC Production هنوز فعال نیستند.

## روش تست ساده

## ذخیره‌سازی قابل انتقال سناریوها

تعریف سناریوها و تنظیمات اجرایی در فایل `config/scenarios.json` نگهداری می‌شود. این فایل بخشی از داده‌های قابل انتقال پروژه است و می‌توان آن را همراه برنامه به سیستم دیگری کپی کرد. صفحه مدیریت سناریو هنگام ذخیره، همین فایل را از طریق API محلی به‌روزرسانی می‌کند؛ `localStorage` مرورگر فقط نقش پشتیبان دارد.

برای دریافت خروجی قابل انتقال، پس از اجرای سرور محلی این مسیر را باز کنید:

`http://127.0.0.1:8765/api/scenarios/export`

در این نسخه، Snapshot مربوط به Case، Note، Task، Post و KB در `data/pargar-support.sqlite3` ذخیره می‌شود و هیچ داده‌ای در CRM ثبت نمی‌گردد.

فرم مدیریتی Release 0 برای تصمیم‌گیری است و ابزار تست نیست؛ برای تست آن را باز نکنید.

1. فایل `run-app.bat` را اجرا کنید.
2. View پیش‌فرض انتخاب می‌شود؛ روی «واکشی Caseهای این View» بزنید.
3. از فهرست Caseها یک مورد را انتخاب کنید.
4. فقط این سه مورد را بررسی کنید:
   - آیا پیشنهادهای اصلاحی کمبود واقعی Case را درست فهمیده‌اند؟
   - آیا مقالات مرتبط از KB واقعاً به موضوع Case مربوط‌اند؟
   - آیا نتیجه پیشنهادی با Case و Timeline آن سازگار است؟
5. پذیرش یا رد پیشنهادها فقط بازخورد محلی ثبت می‌کند و CRM را تغییر نمی‌دهد.

## سناریوی مرحله‌ای

صفحه [`scenario-checklist.html`](scenario-checklist.html) برای اجرای مرحله‌به‌مرحله سناریوهای Helpdesk است. سناریوی «بررسی کندی سیستم» اکنون شامل ۶ مرحله اصلی ارائه‌شده توسط کاربر و ۴ بررسی تکمیلی پیشنهادی برای تشخیص اولیه است. کارشناس در هر مرحله نتیجه را ثبت می‌کند و در پایان یک متن کامل و قابل کپی برای CRM یا ارجاع به L2 دریافت می‌کند.

جزئیات محدوده و معیار پذیرش این قابلیت در [`release-2-smart-troubleshooting.md`](../release-2-smart-troubleshooting.md) ثبت شده است.

در هر مرحله، موضوع سؤال و پاسخ انتخاب‌شده در مقالات KB داخلی جست‌وجو می‌شود. اگر مقاله مرتبط با شواهد کافی پیدا شود، شماره، عنوان، واژه‌های منطبق و بخشی از شاهد نمایش داده می‌شود؛ اگر پیدا نشود، برنامه مقاله نامرتبط پیشنهاد نمی‌دهد.

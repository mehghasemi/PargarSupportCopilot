# Release 1 — کیفیت ورودی Case و پیشنهاد KB

**تاریخ شروع پیاده‌سازی:** ۱ سپتامبر ۲۰۲۶  
**وضعیت:** پیاده‌سازی محدود و قابل تست  
**خارج از محدوده:** Smart Troubleshooting (Release 2)، ثبت خودکار در CRM و پاسخ خودکار به مشتری

## هدف

کمک به کارشناس L1 برای تشخیص کمبود واقعی Case و یافتن حداکثر سه مقاله KB دارای شواهد متنی؛ تصمیم نهایی و ثبت رسمی همچنان با کارشناس است.

## جریان کار

1. کارشناس یک Case را از Snapshot انتخاب می‌کند.
2. Case، Note، Post و Task مرتبط خوانده می‌شوند.
3. فیلدهای ضروری و کیفیت محتوایی Title، Description و اقدام/نتیجه بررسی می‌شود.
4. کمبودها با سؤال آماده نمایش داده می‌شوند.
5. عنوان و محتوای مقالات KB رتبه‌بندی واژه‌ای می‌شوند.
6. حداکثر سه مقاله با کلمات منطبق و بخشی از شواهد نمایش داده می‌شود.
7. کارشناس پیشنهاد را می‌پذیرد، ویرایش می‌کند یا رد می‌کند.
8. بازخورد فقط در SQLite داخلی ذخیره می‌شود؛ CRM تغییر نمی‌کند.

## معیار کیفیت Case

پر بودن فیلد کافی نیست. عنوان باید توصیفی باشد، شرح باید برای فهم مسئله قابل استفاده باشد و در Case یا Timeline باید شاهدی از اقدام/نتیجه وجود داشته باشد. مقدارهای عمومی، متن بسیار کوتاه و بدون شاهد، Case کامل محتوایی محسوب نمی‌شوند.

## خروجی فنی

- `quality.is_content_complete`
- `quality.issues`
- `quality.quality_rule`
- `articles[]` شامل شماره مقاله، عنوان، امتیاز، کلمات منطبق، شواهد و دلیل
- `feedback` محلی با یکی از وضعیت‌های پذیرفته‌شده، ویرایش‌شده یا ردشده

## معیار پذیرش

- Case ناقص حداقل یک کمبود قابل توضیح نشان دهد.
- Case دارای فیلد پر اما متن صوری به‌عنوان کامل محتوایی پذیرفته نشود.
- مقاله بدون محتوای کافی نمایش داده نشود.
- پیشنهادها منبع و شواهد داشته باشند.
- هیچ Endpoint این Release در CRM عملیات نوشتن انجام ندهد.

## محدودیت

رتبه‌بندی KB فعلاً تطابق واژه‌ای است و درک معنایی/Embedding ندارد؛ بنابراین پذیرش مقاله همیشه نیازمند بازبینی کارشناس است.
